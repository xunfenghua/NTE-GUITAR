# NET-GUITAR：MIDI 到可弹奏钢琴、吉他与键盘的算法和转换逻辑

**源码基准：** NET-GUITAR 当前工作区（2026-10-20）  
**文档用途：** 说明 MIDI 音符如何经过选曲、选轨、音高/时间处理，变成各目标乐器可以执行的游戏按键和鼠标动作。  
**阅读提示：** 本文按代码实际行为整理；“键盘”指旧的 36 键模式，“游戏钢琴”指独立校准布局功能。

## 1. 先说清三种目标

工程内乐器 ID 和调用链不是同一条：

| 目标 | ID | 输入/输出形态 | 主要编译器 |
|---|---:|---|---|
| 36 键键盘 | 0 | MIDI 音高 → E3–D#6 的 36 个音符索引 → 用户键位预设 → 键盘按下/抬起 | `MidiConverter` → `ActionCompiler` |
| 吉他 | 1 | 旋律/和弦音符 → 六弦品位或游戏和弦/扫弦/拨弦动作 | `FretConverter` + `GuitarCompiler`，或完整混合的 `HybridGuitarCompiler` |
| 游戏钢琴 | 2 | MIDI 音高 → 校准的七键/十二键布局绑定（可带修饰键）→ 键盘动作 | `PianoMidiCompiler` |

传统转换弹窗对外提供 36 键和吉他两种目标；游戏钢琴在独立的 Piano 页面/会话中使用专门的布局配置、校准和编译。三者共享 MIDI 读取与原始音符数据，但映射、可弹奏约束和动作编译不能互相替代。

## 2. 总体转换流程

```text
MIDI 文件
  └─ MidiLoader：读取轨道/音符/节拍速度图，统一转换为微秒时间轴
      └─ 原始 RawMidiNote（音高、起点、时长、力度、声道、轨道、GM Program）
          ├─ 轨道选择、鼓轨过滤、旋律/全曲识别（按目标和用户选项）
          ├─ 目标专属预处理：移调、折叠、降复音、和弦识别、节奏缩放
          └─ 目标编译器：物理可奏音符/指法/键位冲突规划
              └─ 按时间排序的 KeyDown/KeyUp、琴弦、翻页、选槽、扫弦等动作
                  └─ 调度器按绝对时间批次执行，并在必要时释放所有按键
```

关键数据单位是微秒（`long`）。`RawMidiNote` 保存 `StartUs`、`DurationUs`、`NoteNumber`、`Velocity`、`Channel`、`TrackId`、`Program`；音符时长仍是 MIDI 输入属性，是否作为按住时长取决于目标编译器。

## 3. MIDI 读取与公共预处理

### 3.1 解析与时间轴

`MidiLoader.Load` 用 DryWetMIDI 解析文件，并对文件字节计算小写十六进制 SHA-256。随后读取全文件 Tempo Map，将每个音符的起始 tick 与时长分别转换为 `MetricTimeSpan.TotalMicroseconds`，因此中途变速也会反映到绝对时间轴。音符包含所属 Track、Channel、Velocity 和轨道首个 Program Change。轨道元数据另存轨道名、Program、音符数、声道集合和音域。

解析设置会容忍部分不完整/异常 chunk；velocity 0 的 Note On 按 Note Off 解释。结果按起音时间、再按音高排序，并以文件 SHA-256 写入 raw cache。缓存的是原始音符数据，后续转换选项不应污染它。

### 3.2 选轨、鼓轨与识别模式

`ConvertOptions` 记录移调、是否忽略鼓通道、音域外策略、启用轨道 ID、目标乐器和识别模式。MIDI Channel 是 0 起始编号；Channel 9 即标准 MIDI 第 10 声道，常用于鼓。

- `EnabledTracks == null` 表示全部轨道；否则只保留所选 TrackId。
- 通用 36 键转换默认过滤 Channel 9，并对音符做选轨；之后进行用户移调和音域处理。
- 吉他可选“完整多音”或旋律识别。已识别为单音的旋律会传递来源标记，避免吉他品格转换器再次误删琶音/短连音。
- 游戏钢琴编译器按 `FilterDrumChannel10` 过滤鼓声道；其输入轨道选择通常在构造/载入曲目时完成。
- `EffectiveSongNotes` 会优先用 `SelectedRawNotes` 重建吉他源流；对老版本曲库则根据保存的选轨、鼓轨和识别模式回算。播放覆盖层与导入曲目的源流由此保持一致。

### 3.3 主旋律识别候选

当输入多轨全曲而用户选择旋律模式时，`RecognitionService.GenerateAllCandidates` 生成候选：

| 模式 | 主要规则 |
|---|---|
| `FullSong` | 原样保留全部传入音符和复音。 |
| `TrackPriority` | 先按轨道打分并选择一轨：轨名含 vocal/melody/lead/solo 等加分，bass/drum/chord/pad 等扣分；再结合 GM Program、平均音区和音符密度。单轨时直接返回。 |
| `HighestNote` | 18ms 起音窗内取最高音；可去除短装饰音和极端孤立高音，遇到与前音相差至少 14 半音而第二高音只差不超过 6 半音时改选第二高音。 |
| `ContinuousMelody` | 20ms 切片，每片最多保留 4 个高音/长音候选；以力度、时值、lead 轨名和音高计算局部分；Viterbi 动态规划跨片选总分路径。当前默认 `UseTransitionBias=false`，不强行把原曲大跳改成级进。 |
| `Monophonic` | 以 TrackId+Channel 作为声部，对至少 10 音的声部计算单音比例、音区和 GM Program 分数；选择最佳声部，再把 20ms 内并发音压成最高音。 |
| `AutoLeadFusion` | 对轨道计算名称/Program/音域/密度/复音率先验；选最多 5 条高分轨并保留明确 lead 轨；25ms 分组，每组 Top-3 加显式 REST；Viterbi 结合本地显著度、音程连续性、同轨奖励和跨轨惩罚选出融合主旋律。 |

识别是在音符流上做候选抽取，不会恢复 MIDI 中不存在的声部信息。选择 `FullSong` 则不会去除伴奏。吉他覆盖层的特殊规则：单轨 FullSong 直接保留；多轨 FullSong 在覆盖层可尝试 AutoLeadFusion，以免和弦伴奏挡住画面主旋律。

## 4. 36 键键盘：音高索引与按键动作

### 4.1 音高归一化

目标音域是 MIDI 52（E3）至 87（D#6），共 36 个半音键。处理顺序：

1. 确保输入按 `StartUs` 排序；
2. 跳过 velocity 0、可选鼓通道、未启用轨道和非法音高；
3. 计算 `n = clamp(NoteNumber + Transpose, 0, 127)`；用户移调配置通常为 -24 至 +24 半音；
4. 若 `OutOfRangeMode == OctaveFold`，反复加/减 12，直到落在 [52,87]；否则超范围音符丢弃；
5. 计算 `NoteIndex = n - 52`，得到 0..35；
6. 对同一 `StartUs`、同一 NoteIndex 的重复音去重；不同起音时间仍保留；
7. 按时间、NoteIndex 排序，保存 `GameNoteEvent(TimeUs, NoteIndex, DurationUs)`。

例：MIDI 60（C4）→ `60 - 52 = NoteIndex 8`。如果 MIDI 48 且八度折叠，则提升到 60 后映射为索引 8；若 Discard 则丢弃。

曲库保存的是音符索引而不是扫描码。`ActionCompiler` 播放时再通过当前键位预设把 NoteIndex 转成 `(ScanCode, Extended)`。改键不会要求重新导入 MIDI。

### 4.2 按键脉冲、重复音与延音

`ActionCompiler` 对每个音符索引找预设映射，按物理键分组；同一个物理键同一时刻只产生一个攻击。默认参数为 Tap 30ms、最短按住 20ms、最小释放间隔 2ms、动态延音默认关闭。

- 基础时长至少 20ms；延音开启时，只有 MIDI 时值比 Tap 长且该音是全曲尾音，或距全曲下一个起音及同键下一次起音都不少于 280ms，才按原时值（上限默认 1.5s）延长。
- 密集段始终用短脉冲，防止多个物理键长时间同时按住。
- 同物理键下一击若太近，则把下一次按下推到前次 KeyUp + ReleaseGap；同一物理键同刻重复会合并，不同时间的快速重复音保留。
- 动作按时间排序，同刻先 KeyUp 后 KeyDown；同刻动作组装为一个 `InputBatch`，和弦可以一次批量发送。

## 5. 游戏钢琴：布局映射与键冲突调度

### 5.1 布局、校准和合法映射

钢琴布局由已验证的扫描码绑定构成，音符键的真实映射来自校准配置。编译前先验证布局结构；未校准/缺扫描码/重复扫描码等会生成错误并阻止启动。所有动作最终使用扫描码及 Extended 标志，而不是按当前键盘布局猜字符键。

钢琴可用目标 MIDI 范围默认是 48..83（C3..B5，36 个半音）；`FoldIntoPlayableRange` 保留音级，按八度上下折叠到可用范围。候选范围会结合布局中有效自然音键的实际基准音高扩展。

#### 十二键半音布局

对每个已验证自然音键建立候选：

- 直接键：`BaseMidiPitch == targetPitch`，不需要修饰键；
- Shift 键：`BaseMidiPitch + Shift.SemitoneDelta == targetPitch`；
- Ctrl 键：`BaseMidiPitch + Control.SemitoneDelta == targetPitch`。

只接受已验证、有效扫描码、非零半音偏移的修饰键。排序优先级为：调用方指定的 preferred modifier、无修饰键、基准音高距离、音区 Row、键位 Position。无首选 modifier 时，直键优先于 Shift/Ctrl。

#### 七键调式布局

布局指定中音区主音 MIDI 与 7 个升序调式间隔（第一项 0）。把音符先按八度折叠到 `Tonic-12 .. Tonic+23`，计算相对主音的 octave 与 pitch class：

- octave < 0 → Low；= 0 → Middle；> 0 → High；
- pitch class 在调式间隔中时精确映射到对应 degree 1..7；
- 若原音不在调式内，选择环绕半音距离最近的音级，平局取较小 degree index；该步骤会改变实际音高音级并报告适配。

最终要求对应 Row+Position 的键绑定存在、扫描码有效且验证通过；否则该音符跳过。

### 5.2 自动整体移调

用户手动移调非零时不做自动移调。否则遍历整体偏移 `[0,-12,+12,-24,+24,-1,+1,-2,+2]`，对每个音符估算得分：时长权重 `clamp(DurationUs/100ms,0.5,6)` × 力度权重 `clamp(Velocity/100,0.25,1.27)`；精确落在音域加 12×权重，折叠后加 4×权重，55..79 音区再加 1.5×权重，自然音级再加 1.25×权重，超出 MIDI 0..127 扣 2×权重。偏移本身另扣 `0.65*abs(shift)`。得分最高的同一个 shift 应用于全曲，保留音程关系。

### 5.3 时间缩放和事件规划

速度范围夹在 25%..200%。绝对时间缩放公式为：

```text
scaledTimeUs = round(timeUs * 100 / speedPercent, AwayFromZero)
```

音符开始/结束分别缩放，时长至少 20ms；负起音、溢出、无绑定事件跳过。默认规则：最短按住 20ms、同键重触发间隔 8ms、和弦修饰键组错开步长 22ms、修饰键提前量 2ms、修饰键脉冲保持 20ms、和弦起音簇窗口 15ms。

### 5.4 同刻和弦冲突解决

按开始时间升序、同刻高音优先建立 15ms 时间簇，随后执行：

1. 同 `(音符扫描码, Extended, Modifier)` 重复映射只保留时长最长的音；
2. 若布局声明的“已验证最大复音数”被超过，保留最高音；上限至少为 2 时还保留最低音，剩余名额从中间音中依序补齐；
3. 十二键簇如果同时需要 Shift 和 Ctrl，尝试把 Ctrl 音改成等价 Shift 候选；
4. 若仍有多个修饰键组，按 lead modifier 优先排序，随后每个组晚 22ms 起音，并整体平移结束时间；
5. 最后按物理音符扫描码分组，检查前音结束是否侵入下一音的 8ms 重触发间隔。必要时截短前音；保证最短按住时长，并在极端情况下推迟下一击。

修饰键不是整段与音符一起按住：按同一 modifier 的音符起音生成脉冲，按住 20ms；相邻脉冲起点不超过前脉冲结束+4ms 时合并。排序规则是 KeyUp、ModifierUp、ModifierDown、KeyDown，确保同刻先释放、再按下。

## 6. 吉他：从音符到指法/和弦动作

当前代码有两套吉他编译策略，应分开理解：独奏品格转换、传统和弦动作编译，以及“吉他完整混合演奏”按帧做全局模式决策。

### 6.1 标准调弦、音域、品页/槽位

标准六弦 EADGBE（代码按 1 弦到 6 弦存储）开弦 MIDI：1弦 E4=64、2弦 B3=59、3弦 G3=55、4弦 D3=50、5弦 A2=45、6弦 E2=40。有效品位 0..24，范围 MIDI 40..88。

品位 `f` 到游戏轮盘页/槽位：

```text
f == 0       => P5 / S1（空弦）
f in 1..24   => page = floor((f-1)/6)+1
                slot = ((f-1) mod 6)+1
```

每个音在六根弦上试算 `fret = note - openString`，先列举 1..24 品候选；只有无高把位解时才把空弦 0 品作为候选。超出总音域的音不会夹成最近音，而是给 DP 一个 Skip 节点。

### 6.2 独奏保护、统一八度与 Viterbi 指法

如果上游已经输出标记为单音的旋律，`SanitizeForFretSolo` 只过滤鼓轨并直通。否则按 15ms 起音容差把并发和弦缩为最高音（同音时选力度更大者）；相同音高的稍后重击会开始新组，避免连击被吞。这里用起音并发判定，不依据音符尾部重叠来吞音。

统一八度 shift 候选包括固定 `{0,±12,±24}`，并动态加入 -48..+48 中能让原音域与吉他音域有交集的八度。每个音按时长与力度加权：可奏加 10×weight；超音域扣 50×weight；超过 MIDI 84 对高把位轻微扣分；整体 shift 扣 `20*abs(shift)`，强烈保持原调。此全曲 shift 保留旋律音程，不逐音 Clamp。

随后每个音的可用 (弦, 品) 作为 DP 一层，状态代价包含：高把位代价（0..12 品零代价、13..18 每品 0.6、19..24 每品 2.0）、不符合高/中/低音自然弦位的代价、翻页、换槽、换弦/手位移动和快速连奏切换惩罚。DP 对全曲路径求最低总代价；发生时序上赶不及翻页/换槽时，优先标出 timing conflict 并保留可奏音（加 250 惩罚），而不是悄悄落到旧品位；若本来就无可奏音才 Skip。首个可奏音禁止以“来不及准备”为由跳过，预滚动准备起始页。

核心转换代价硬约束：页面切换按 `PageKeyHold + InterTapGap` 串行计时；换页后选槽再加轮盘稳定时间及安全余量；同页换槽也必须给鼠标稳定时间。若相邻起音间隔小于所需准备时间，状态转移标为不可行，再由 DP 的冲突兜底处理。快速连奏（<320ms）更偏好同页同槽；高把位/异弦也有手位成本。

### 6.3 传统吉他动作编译

`GuitarCompiler.CompileFretEvents` 把品格事件变成游戏输入：目标弦键按住/释放；新页通过 R/T 等翻页键逐次执行；轮盘选槽通过鼠标移动/点击；需要时拨弦。动作生成会考虑速度、调度安全裕量和物理动作的先后依赖，并把跳过事件从真正发声中滤除。翻页和鼠标选槽不能像 MIDI 和弦那样简单同时按下。

传统和弦分析/编译使用 `ChordAnalyzer` 或 V2 对 24 个游戏和弦打分并产生 ChordEvent；之后按 preset、扫弦/拨弦模式和动作计时生成和弦页/槽位、拨弦弦号或鼠标扫弦。V2 的和弦表保存每个游戏和弦 6→1 弦的实际发声音高，拨弦应根据游戏的真实弦音而非想象中的标准和弦指法判断。

V2 默认只将 MIDI 起音时间完全相同的音符归为同一次攻击；不同轨道相隔几毫秒的拨弦也分别生成事件。和声观察窗为 320ms，最短和弦稳定时间为 240ms，迟滞为 0.14。自动半音移调遍历 -6..+5：按音级统计加权证据（时长、力度、低音 boost），与游戏 C/G 和弦体系的音级权重相乘，再轻罚偏离原调。逐窗和弦评分综合：和弦覆盖 0.62、完整度 0.26、根音/低音奖励、和弦页先验、非和弦音惩罚；Strict 增大非和弦音罚分，BassRoot 强化低音证据。切换需满足稳定时间和迟滞，避免装饰音造成频繁换槽。同一物理弦需要重拨时，先在满足最短按压时间后提前释放前音，再按原起音时间触发后音。

### 6.4 吉他完整混合：自动降复音 + 自动配速 + 帧级模式规划

`HybridGuitarCompiler.CompileFullPerformance` 是能在品格/固定和弦之间切换的完整路径：

1. `MidiPolyphonyReducer` 丢弃鼓轨、velocity<12、时长≤5ms，以及特定 Pad Program(88..103) 中超过 1.5 秒的持续音；默认只合并起音时间完全相同的音符，跨轨连续拨弦保留各自时间；同音去重时保留力度最高、再保留时长较长者；同刻最多 6 声部，优先主旋律、高音和低音，再按力度补足不同音级。
2. `MidiSpeedOptimizer` 检查起音间隔。相同最高音簇至少需满足按住+释放（默认 20+8=28ms）；大音程跨槽/翻页需要更多准备缓冲；短 MIDI 时值也可提出适度拉伸。根据已排序需求系数的配置分位选择 targetScale，若小于等于 1 保持 100%，否则推荐 `floor(100/targetScale)`，夹在 25..100%。用户手动速度优先于导入时的自动建议。
3. 按生效 timeScale 缩放起音和时值，时值不低于 20ms。
4. `ChordAnalyzerV2` 在缩放后的音符上识别和弦，同时求全局半音移调，再由 `FretConverter.FindBestGlobalOctaveShift` 求整体八度；超吉他音域音符被过滤。
5. 按完全相同的 MIDI 起音建立演奏帧。每帧去重音高后按高音优先生成候选：品格分支尝试最高主旋律音的所有可行弦/品，并只附加可在同品、不同弦同时发出的其它音；和弦分支只在检测到的游戏和弦表有匹配时产生扫弦、Block 或 Arpeggio 候选。主旋律活跃/被保护时，和弦候选必须能真实保留主旋律音高；副旋律场景允许八度等价弦。
6. Viterbi 对帧候选全局求最低代价，代价包括丢失伴奏音、切换模式、翻页数、换槽、轮盘稳定耗时和距离当前动作的可准备时间。切入不同模式会按游戏行为将品格页重置到 P1，因此按切换后相对 P1 计算页面准备；时间来不及的转换不可选。长音/旋律保护帧可加入保持现位置状态；空的保持状态仍计入漏音代价，让当前位置可弹出的琴弦音优先发声。
7. `EmitHybridActions` 将路径输出成键盘、翻页、选槽、拨弦、鼠标扫弦指令，确保最短按压并按动作优先级排序。同一物理弦连续重拨时，依据下一次起音截短前音延音，避免后音被前音原始时长推迟。超出演奏音域的音符会跳过，不逐音夹成错音。

混合模式总体策略：优先保持高音主旋律的确切音高；目标和弦实际音响能保留当前主旋律时生成和弦候选，再由全局路径判断切入与退出时机。连续拨弦可一直留在同一和弦页和槽位，无须为每个临近主旋律音反复切回品格。伴奏可以精简，主旋律的 pitch 真实性优先。

## 7. 调度与实际输入保护

编译器输出动作时间是相对歌曲开始的绝对微秒。播放服务/会话调度器在目标窗口校验后，按同一时间戳把动作合批发送；避免每个音都按相对 Sleep 累加造成节奏漂移。吉他调度器还处理 R/T 翻页、模式 Z 切换、鼠标轮盘和拨弦等串行动作。

键盘发送统一按扫描码注入；预设/钢琴 Profile 把音符逻辑和物理键位分离。常规播放在焦点离开目标游戏窗口时停止；正常终止、异常中断、发送失败等路径会做 release-all 清理，避免键卡住。吉他动作失败会写诊断/跳过原因；播放音高试听可用 `PlaybackPitchProjection` 根据最终钢琴/品格编译事件生成 MIDI 预览，避免试听与实际编译选择不一致。

## 8. 转换策略对比

| 特性 | 36 键键盘 | 游戏钢琴 | 吉他品格 | 吉他完整混合 |
|---|---|---|---|---|
| 主要音域 | 固定 MIDI 52–87 | 默认 MIDI 48–83；可按布局基准调整 | 标准调弦 MIDI 40–88 | 40–88；范围外丢弃 |
| 八度处理 | 每音八度折叠或丢弃 | 全曲自动移调 + 每音八度折叠；七键还可能吸附到音阶 | 全曲统一八度选择；不逐音夹音 | 和弦半音全曲移调 + 全曲八度选择 |
| 复音 | 保留全部映射音；同刻同索引去重 | 布局实测复音上限可削减，修饰键冲突错开 | 独奏识别/并发最高音；单音状态 DP | 上游最多 4 音/帧，和弦模式可扫弦/分弦 |
| 可弹奏规划 | 键位表映射 | 校准键位、修饰键、重击约束 | 六弦候选 + 全曲 DP | 帧候选 + 模式切换 Viterbi |
| 时间/速度 | 原时间轴 + 脉冲释放保护 | 25–200% 时间缩放 + 20ms 最短按键 | 物理准备时间用于可达性判断 | 自动建议 25–100% 并显式规划物理动作 |
| 失配策略 | 超范围丢弃或折叠 | 缺失键位跳过，报告 issue | 超出音域 Skip，不用错音代替 | 超出音域过滤/不可奏状态不选 |

## 9. 参数和算法结果如何影响曲库

转换后的 `ConvertedSong` 保留目标类型、来源名/hash、转换选项、识别模式、归一化 `Notes`，也可保留原始 `RawNotes` 及选择后的 `SelectedRawNotes`。曲库 meta 保存检索所需信息；原始 MIDI 删除后，已归一化 36 键歌曲仍可直接播放。36 键曲库存索引而非物理按键，因此更换预设可即时生效。

游戏钢琴的已编译 PianoAction 是播放会话结果，布局/profile 与校准关系仍要存在，不能只拿 36 键 `NoteIndex` 替代钢琴扫描码绑定。吉他需重建指法、和弦及物理轮盘动作，也不能把 36 键的 NoteIndex 直接当品位或琴弦。

## 10. 已知边界与阅读代码时的注意事项

- MIDI 的 GM Program 和轨道名只是旋律识别先验，不会改变 MIDI 音高本身，也不会自动改变目标游戏音色。
- `Transpose`、`OutOfRangeMode` 与 Piano 的 `TransposeSemitones` 是不同编译入口的参数；Piano 的自动整体移调是独立评分。不要把通用键盘的逐音八度折叠和吉他的全局八度选择混为一谈。
- 七键模式为了适配调式，会把非调内音移到最近音级；十二键模式保留半音，但可能通过折叠改变八度。
- 36 键 `MidiConverter` 同时保留 `RawNotes` 和转换后的 `Notes`；播放用已转换流。`EffectiveSongNotes` 对吉他可能重建源音流，需依据保存的选轨和识别配置。
- 吉他两条路径对复音的策略不同：品格独奏通常压成单音主旋律；完整混合模式保留最多 4 个音并尝试真实和弦状态。
- 吉他标准调弦及页槽编码描述的是当前实现；若游戏自定义调弦、轮盘页数或按键映射改变，候选生成与调度参数也必须相应调整。
- 游戏钢琴布局扫描码是否正确依赖真实校准，算法不会凭 MIDI 自动推断用户电脑键盘布局。
- 速度优化只是依据已建模的物理时间预算推荐速度；实际帧率、窗口焦点、输入丢失和硬件延迟仍会影响演奏结果。
